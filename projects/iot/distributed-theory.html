Distributed Training Theory

Foundations of large-scale ML training systems

Data Parallelism

Data parallelism replicates the model across multiple devices, with each device processing a different mini-batch. Gradients are synchronized via all-reduce operations.

$$\nabla_\theta \mathcal{L} = \frac{1}{N}\sum_{i=1}^{N} \nabla_\theta \mathcal{L}_i$$

Synchronized gradient averaging across N workers

Synchronous SGD

All workers compute gradients, synchronize via all-reduce, then update. Equivalent to large-batch training.

Asynchronous SGD

Workers update independently with stale gradients. Higher throughput but potential convergence issues.

ZeRO Optimization

Zero Redundancy Optimizer partitions optimizer states, gradients, and parameters across data-parallel ranks to reduce memory footprint.

ZeRO Stage 1 - Optimizer State Partitioning

Partition optimizer states (e.g., Adam momentum and variance) across ranks.

$$\text{Memory} = \Psi + \Psi + \frac{K\Psi}{N_d}$$

Parameters + Gradients + Partitioned Optimizer (K=12 for Adam FP32)

ZeRO Stage 2 - Gradient Partitioning

Additionally partition gradients. Each rank only stores gradients for its optimizer partition.

$$\text{Memory} = \Psi + \frac{\Psi}{N_d} + \frac{K\Psi}{N_d}$$

ZeRO Stage 3 - Parameter Partitioning

Partition all model states. Parameters are gathered on-demand during forward/backward.

$$\text{Memory} = \frac{\Psi + \Psi + K\Psi}{N_d} = \frac{(2+K)\Psi}{N_d}$$

Tensor Parallelism

Tensor parallelism splits individual layers across devices, enabling training of layers too large for a single GPU.

$$Y = \text{GeLU}(XA) = [\text{GeLU}(XA_1), \text{GeLU}(XA_2)]$$

Column-parallel MLP: Split weight matrix A along columns

Column Parallelism

Split weight columns across GPUs. Each GPU computes partial output. Requires all-reduce after second linear.

Row Parallelism

Split weight rows. Requires all-reduce before the layer. Often combined with column parallel.

$$\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V$$

Attention heads are naturally parallelizable across devices

Pipeline Parallelism

Pipeline parallelism partitions model layers across devices, with micro-batches flowing through the pipeline.

$$\text{Bubble Ratio} = \frac{p-1}{m}$$

where p = pipeline stages, m = micro-batches

GPipe

Fill pipeline with micro-batches, then drain. Simple but has bubble at boundaries.

1F1B

Interleave forward and backward passes. Reduces memory from O(m) to O(p).

Interleaved

Multiple model chunks per device. Reduces bubble by factor of v (virtual stages).

Communication Primitives

Efficient collective communication is critical for distributed training performance.

All-Reduce

Reduces values across all ranks and distributes the result to all ranks.

$$T_{ring} = 2(n-1)\left(\alpha + \frac{S}{n \cdot B}\right)$$

Ring all-reduce: α=latency, S=size, B=bandwidth, n=ranks

All-Gather

Gathers data from all ranks to all ranks. Used in ZeRO-3 for parameter gathering.

Reduce-Scatter

Reduces and scatters result chunks. Used in ZeRO-2+ for gradient reduction.

Activation Checkpointing

Trade compute for memory by recomputing activations during backward pass instead of storing them.

$$\text{Memory} = O(\sqrt{L}) \text{ with } O(\sqrt{L}) \text{ recomputation}$$

Optimal checkpointing for L layers

  • Full Checkpointing: Store only layer inputs, recompute all activations
  • Selective Checkpointing: Only checkpoint expensive operations (attention, FFN)
  • Segment Checkpointing: Checkpoint every N layers optimally

Scaling Laws

Understanding how model performance scales with compute, data, and parameters.

$$L(N, D) = \left(\frac{N_c}{N}\right)^{\alpha_N} + \left(\frac{D_c}{D}\right)^{\alpha_D}$$

Chinchilla scaling: N=parameters, D=tokens, α≈0.34

Compute-Optimal Training

For fixed compute budget C, optimal allocation: N ∝ C^0.5, D ∝ C^0.5

Training FLOPs

Approximate: C ≈ 6ND for dense transformers (forward + backward)

Mixed Precision Training

Use lower precision (FP16/BF16) for compute while maintaining FP32 master weights.

$$w_{t+1} = w_t^{(fp32)} - \eta \cdot \text{scale} \cdot g_t^{(fp16)}$$

Loss scaling prevents gradient underflow in FP16

  • FP16: 2x memory reduction, but requires loss scaling
  • BF16: Same dynamic range as FP32, no loss scaling needed
  • FP8: 4x reduction, requires careful quantization (H100+)
